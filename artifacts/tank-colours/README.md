# Tank colour implementation

Implemented locally on 2026-10-26, based on commit `2829c636546ac4d402b015b37241c48e0abf31cb`. These are Unity Editor renders of the actual delivered meshes, not generated artwork or screenshots of a released player. A local Web preview is built for localhost; public sites and the APK remain unchanged.

## Assignment

- Player identity comes from `TankState.Player` and `Slot`, not chassis or team: Player 1 `#35C759`, Player 2 `#F5B82E`, Player 3 `#168BFF`, Player 4 `#A855F7`. Offline slot -1 is Player 1. All four chassis use this mapping.
- Solo/co-op NPCs and context-free previews use primary `#343A46` and secondary `#687384`. In PvP, allied NPCs use that same gunmetal/steel-grey treatment; hostile NPCs use red `#C55343` / `#E88970`. Heavy Armoured NPCs (bunker chassis, tier 3) are darker: `#1C222C` / `#3E4857` neutral/allied, `#7F302A` / `#A85243` hostile PvP. This supersedes the initial cyan-blue ally treatment. Classification follows the simulation's alliance rules relative to the local player and refreshes if that relationship changes. Human player colours stay slot-based.
- Power-droppers smoothly pulse their whole painted hull, turret and barrel sleeves between glowing red and neutral gunmetal/steel-grey over a 0.6-second cosine cycle, including red-painted PvP carriers. Armour emission reaches zero at the grey phase. Existing red accents also fade; tracks, mechanics and markings remain intact. Simulation time keeps pause/replay consistent. Renderer property blocks leave cached/shared materials and power-up drop visuals untouched. Losing the Drop flag rebuilds the ordinary NPC appearance in its faction colour and removes the pulse. Ordinary red NPCs remain solid red. This supersedes the initial accent-only, hard on/off blink and return-to-red-faction-colour pulse.
- Normal/Armoured NPCs use orange-red lenses. Speed uses amber lenses and barrel trim. The existing tier-2 Fast-shell NPC uses red-orange painted barrel sleeves/trim. Power Droppers keep their mode-appropriate armour with red lenses and hatch trim; this remains a flag on the existing NPC classes.
- Existing imported PBR materials are cloned into a source-material/colour cache, retaining shaders, textures, metalness and roughness. Dropper armour copies additionally enable the emission shader variant; other keywords remain intact. Untinted materials retain their original references. Runtime clones use the game's existing material ownership/disposal list; guide clones have their own cache and cleanup. No original material is mutated.
- The render identity is derived from already replicated Player/Slot/Tier/Drop fields; no protocol, authority, spawn or simulation fields changed. The actor refreshes its appearance when those identity inputs change. Existing combat effect colours are separate and untouched.

## Changed source files

- `Assets/BattleCities/Runtime/BattleTankAppearance.cs`: authoritative surface palette and cached material copies.
- `Assets/BattleCities/Runtime/BattleTankDropperBlink.cs`: whole painted armour blinking via per-renderer overrides for marked NPCs.
- `Assets/BattleCities/Editor/DropperGlowBuild.cs` and `Assets/BattleCities/Resources/RuntimeShaders/TankDropperGlow-0.mat`: retain the single required emissive shader variant in stripped player builds without changing the original model materials.
- `Assets/BattleCities/Runtime/BattleGame.cs`: live and replay actor surfaces and identity refresh.
- `Assets/BattleCities/Runtime/BattleGame.CombatEffects.cs`: comment documenting the independent, unchanged effects palette.
- `Assets/BattleCities/Runtime/BattleGame.EditorPreview.cs`: same colours for level-editor scene models.
- `Assets/BattleCities/LevelEditor/LevelEditorPaletteAppearance.cs`: palette thumbnail regeneration uses the same surface selection.
- `Assets/BattleCities/UI/Runtime/BattleGuideTankPreview.cs`: actual 3D guide previews use Player 1 colour and release their cached materials.
- `Assets/BattleCities/Editor/TankColourChecks.cs`: validation and reproducible evidence captures; new script GUID metadata is generated by Unity.
- `Assets/BattleCities/UI/AGENTS.md`: approved reusable 3D preview colour rule.

No existing meshes, prefabs, materials, animations, GUIDs, power-up art, lighting configuration or packages were modified. Static selection illustrations remain unchanged.

## Validation

Run with:

```powershell
rtk unity run C:/repos/Unity/BattleCitiesUnity --timeout 300 -- -executeMethod BattleCities.Editor.TankColourChecks.Run -logFile C:/repos/Unity/BattleCitiesUnity/Builds/Automation/tank-colours-validation.log
```

See `validation.txt` for the final check count. Checks cover all player/chassis combinations, NPC teams/drop flags, untouched shared surface properties, texture/shader retention, cache reuse, animation/direction, replica round trips and simulation spawns in Co-op, Versus, TeamBattle, CaptureFlag and CaptureFlagDuel. Existing TankStats, ShootingHealth and Multiplayer rules suites also run. Compilation is validated in the Editor; device and live network sessions were not tested.

## Limitations

There is no standalone stationary Bunker NPC class in the current implementation. The heavy Siegebreaker/Bunker chassis already receives player colours and is reused by the existing Armoured NPC. No sixth NPC or stationary behaviour was invented, and no Bunker NPC capture is claimed.

The requested Fast Shooter corresponds most closely to existing tier 2, which has faster shells/firepower rather than a distinct rapid-fire AI profile. Its appearance is updated; its combat statistics and AI remain unchanged.
